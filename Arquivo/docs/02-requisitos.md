# Requisitos do Projeto

## Introdução

Este documento apresenta os requisitos funcionais e não funcionais da landing page do projeto "Conecta Respeito".

Os requisitos descrevem o que a página deve apresentar, como deve se comportar e quais características técnicas devem ser respeitadas durante o desenvolvimento da interface.

## Requisitos funcionais

Requisitos funcionais descrevem as informações e comportamentos que a página deve oferecer ao usuário.

| Código | Requisito funcional | Descrição |
| ------ | ------------------ | --------- |
| RF01 | Exibir cabeçalho | A página deve apresentar um cabeçalho com logo e menu de navegação. |
| RF02 | Navegar pelas seções | O menu deve permitir acesso às principais seções por meio de links internos com âncoras. |
| RF03 | Apresentar mensagem inicial | A página deve possuir uma seção hero com a proposta do projeto e chamada para ação. |
| RF04 | Explicar o tema | A página deve apresentar a definição de bullying e sua importância para a prevenção. |
| RF05 | Apresentar tipos de bullying | Deve existir uma seção com os principais tipos, incluindo físico, verbal, psicológico, social e cyberbullying. |
| RF06 | Apresentar sinais de alerta | A página deve informar indicadores que ajudam a reconhecer situações de bullying. |
| RF07 | Orientar ações seguras | Deve haver orientações sobre como agir de forma adequada e segura diante de uma situação de agressão. |
| RF08 | Informar canais de apoio | A página deve apresentar possibilidades de apoio e orientação para estudantes, famílias e educadores. |
| RF09 | Destacar compromisso coletivo | Deve existir uma seção evidenciando o papel da comunidade escolar na prevenção. |
| RF10 | Exibir rodapé acadêmico | O final da página deve conter identificação da disciplina, do acadêmico e do ano. |

## Requisitos não funcionais

Requisitos não funcionais descrevem características de qualidade, organização, acessibilidade e comportamento técnico da solução.

| Código | Requisito não funcional | Descrição |
| ------ | ---------------------- | --------- |
| RNF01 | Utilizar HTML5 | O projeto deve utilizar HTML5 para estruturar a página. |
| RNF02 | Utilizar CSS próprio | O projeto deve manter o estilo visual em um arquivo separado, em `css/style.css`. |
| RNF03 | Utilizar Bootstrap 5 | O projeto deve empregar Bootstrap 5 para responsividade, navbar, cards e componentes visuais. |
| RNF04 | Ser responsivo | A página deve se adaptar a dispositivos móveis, tablets e desktops. |
| RNF05 | Ter organização de arquivos | O projeto deve manter arquivos organizados em pastas como `assets`, `css` e `Arquivo/docs`. |
| RNF06 | Usar caminhos relativos | Imagens, ícones e arquivos de estilo devem ser referenciados com caminhos relativos. |
| RNF07 | Possuir README | O projeto deve manter um arquivo `README.md` com orientação geral. |
| RNF08 | Possuir documentação técnica | A pasta `Arquivo/docs` deve conter documentação complementar sobre o projeto. |
| RNF09 | Ser versionado com Git | O projeto deve utilizar Git para controle de versão. |
| RNF10 | Estar publicado no GitHub | O projeto deve estar disponível em um repositório GitHub. |
| RNF11 | Ter código legível | O HTML deve possuir organização, indentação e comentários claros. |
| RNF12 | Usar HTML semântico | As tags `header`, `nav`, `main`, `section` e `footer` devem ser empregadas corretamente. |
| RNF13 | Ter metadados básicos | O documento deve conter `charset`, `viewport`, `title`, `description`, favicon e demais metadados no `head`. |
| RNF14 | Permitir publicação direta | O projeto deve manter a estrutura necessária para publicação em ambiente simples, como GitHub Pages. |

## Regras de conteúdo

| Código | Regra | Descrição |
| ------ | ----- | --------- |
| RC01 | Coerência com o tema | Todo o conteúdo deve estar relacionado ao bullying, prevenção e acolhimento. |
| RC02 | Conteúdo educativo | O texto deve ser informativo, objetivo e adequado ao contexto escolar. |
| RC03 | Sem dados sensíveis | O projeto não deve incluir relatos reais, nomes de vítimas ou informações pessoais sensíveis. |
| RC04 | Clareza textual | Os textos devem ser simples, compreensíveis e adequados ao público escolar. |
| RC05 | Caráter informativo | A página deve ser educativa, não funcional como canal de denúncia. |

## Critérios de aceite

A entrega será considerada adequada quando:

- o arquivo `index.html` abrir corretamente no navegador;
- a logo for exibida no cabeçalho;
- o favicon aparecer na aba do navegador;
- o menu permitir navegação interna por âncoras;
- todas as seções obrigatórias estiverem presentes;
- o layout funcionar em desktop e mobile;
- os arquivos estiverem organizados nas pastas corretas;
- o projeto apresentar visual coerente com o tema;
- a documentação da pasta `Arquivo/docs` refletir o contexto do projeto;
- o trabalho estiver versionado em repositório GitHub.

## Observações

Este projeto tem foco educativo e preventivo, não funcionando como sistema de denúncia ou registro formal de ocorrências.

O conteúdo da landing page deve continuar a reforçar a importância do respeito, da empatia e do acolhimento no ambiente escolar e digital.
